# QRC-Eye 交互式像素世界主页总规划

日期：2026-10-01<br>
状态：MVP 本地实现完成；部署与真机验收待做<br>
目标规格：[设计规格](../specs/2026-10-01-interactive-pixel-world-design.md)

## 目标

将 QRC-Eye 首页改造成可探索的 2D 俯视角像素世界，支持角色移动、键鼠/触屏物件互动、项目预览和跳转。提供数据驱动的项目物件接口，使未来新增作品能稳定进入场景。保留语义化主页、静态降级入口、GitHub Pages 根路径部署和现有子项目独立性。

## 技术基线

- 独立子项目 `site-world/`，不新增根目录 `package.json`。
- Phaser 4.2.0 精确锁定版本；TypeScript + ES Modules；Vite 构建；Vitest 单元测试；Playwright 浏览器验收。
- Tiled JSON 地图；PNG spritesheet 和 Aseprite-compatible JSON Hash 动画帧资料；构建生成文件落到 `assets/world/runtime/` 并与源码一同提交。
- 根目录静态 GitHub Pages 保持可直接部署，不在浏览器运行时依赖第三方 CDN。
- 首页默认是全屏 RPG，项目通过世界物件打开；SEO、HUD、说明和异常全屏回退保留语义化 HTML。
- 普通新项目只新增清单记录、场景位置和素材。专属互动通过显式登记的活动模块按需加载。

## 顺序与完成门槛

### Gate 0：开发约束核验

- 实施开始时重新检查 `git status` 与 `index.html` 差异，因为当前工作区有用户未提交更改。
- 核对当时 GitHub Pages 的实际发布方式、主机根路径和静态资源约定；不得因场景工具链变更而覆盖或移走已有网站内容。
- 固定 Node 运行时版本和 Phaser/Vite/Vitest/Playwright 依赖到 `site-world/package-lock.json`。

**通过条件：** 页面直接部署路径和生成目录明确；所有修改的归属有清单；没有改动任何现存游戏内部实现。

### Gate 1：场景底座

- `site-world` 安装、开发、类型检查、单元测试和生产构建可在干净安装后复现。
- 构建输出固定入口文件，首页可以从本站路径加载；禁用 runtime 时静态主页仍完整。
- 首个测试场景只显示色块地图和临时角色，不等待像素美术。

**通过条件：** CI 通过；输出资源无 404；无外部运行时依赖；开发热更新、生产预览均能启动与关闭。

### Gate 2：可玩的世界

- 地图包含入口、可走地面、阻挡物和地点占位符。
- 角色移动、碰撞、四向动画、相机和交互提示通过自动化与目检。
- 桌面和触屏都能打开地点预览；减少动态效果偏好有效。

**通过条件：** 规格 6.2 中涉及场景控制的用例全部通过；地图上的可达空间没有锁死出生点或互动点。

### Gate 3：数据驱动的项目内容

- 项目记录在启动时 schema 校验，位置、资源、状态、路径、互动均有效。
- 首页当前有效项目全部进入注册表并成为地图物件；同一份数据生成全屏异常回退页中的普通 HTML 链接。
- 以“添加一个新项目记录 + 一件新物件”为验收演练；不修改通用场景渲染器即可显示、互动和进入项目。
- 至少一个专属活动模块展示延迟加载契约；初始版本只实现轻量演示，不把完整游戏重写/嵌入主页。

**通过条件：** 新增演练通过构建、单测和 E2E；重复 ID/坏链接/未登记活动必须构建失败。

### Gate 4：主页集成与发布候选

- 全屏场景、HUD、场景内项目物件、预览面板和项目目标页面一致；正常状态无场景下方的项目/笔记/关于区块。
- 桌面 Chrome、移动 Safari/Chrome 和 reduced-motion 模式人工检查；Playwright 检查运行时交互。
- Phaser 或素材加载失败时无黑屏，搜索引擎/无 JS 访客仍能读到项目内容。
- 在构建产物上运行 `verify:dist`，并用本地静态服务器验证生产根路径。
- Lighthouse mobile Performance ≥ 80；检查 JS gzip 与首屏素材预算。

**通过条件：** 规格成功条件全部达成；所有活动子规划的复核项打勾；需要的站点变更和构建资产全部纳入版本控制。

## 数据契约摘要

1. `ProjectManifest` 是项目资料的唯一运行时清单，包含稳定 ID、标题、状态、简介、页面路径、地图位置、物件资源键、命中区域和互动配置。
2. `InteractionSpec` 只允许 `panel`、`navigate`、`activity` 三种类型；activity ID 必须在白名单注册表中。
3. `ProjectObject` 是可复用场景实体，负责显示、排序、命中检测、近距离提示和发出互动事件，不负责维护项目详情文案。
4. DOM 预览层接收带 project ID 的消息，展示标准卡片并将焦点管理留在 DOM；Scene 不创建不可访问的项目正文。
5. 每个专属活动实现共同生命周期（加载、启动、结束/销毁）；退出活动后角色和主世界恢复。

## 风险与控制

| 风险 | 控制措施 |
|---|---|
| 世界互动阻碍访问项目 | 项目各自在地图中有直接可点的物件；项目面板含明确入口，失败时切换到全屏静态回退 |
| 项目逐渐导致单页逻辑膨胀 | manifest + 通用物件 + 显式 activity 注册表；新项目扩展演练纳入验收 |
| 像素图在移动缩放后模糊 | 固定逻辑像素、最近邻缩放、round-pixel 渲染；真实设备验收 |
| Canvas 不利于键盘/屏幕阅读器 | Canvas 有名称与操作提示；HUD、项目面板和全屏回退保持语义化 DOM；项目不只以画布文字表达 |
| 构建输出与源码不一致 | 锁文件、可复现构建、`verify:dist`，CI 检查已提交 runtime 更新 |
| 外部 CDN 或 WebGL 失败 | 本地打包 Phaser；Canvas renderer 回退；HTML 列表保底 |
| 地图内容增长过快 | 第一版限制一张小地图与空地扩展点；新区域按独立子规划审批 |

## 计划外事项

- 不改动博客生成器或各小游戏内部实现。
- 不创建服务端 API、账号、数据收集或线上地图编辑器。
- 不做完整 RPG progression 或要求用户在场景中移动才能找到内容。
- 不更新记忆、发布网站、切换 GitHub Pages 项目设置或创建 PR；这些不属于当前规划请求。

## 规划变更规则

- 子规划可调整实现细节，但不得破坏规格里的成功条件、项目数据契约、静态降级和根路径部署要求。
- 若决定改为纯 Canvas 自研、Three.js 伪 2D 或切换发布方式，先更新本规格和总规划，再开始依赖它的实施。
- 每个子规划通过后更新对应复核清单；所有 Gate 通过后才能把状态改为已完成。
