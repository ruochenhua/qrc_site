# QRC-Eye 俯视角像素世界主页设计规格

日期：2026-10-01<br>
状态：MVP 本地实现完成；2026-10-01 按用户要求更新为全屏 RPG 首页；部署与真机验收待做<br>
总规划：[交互式像素世界主页总规划](../plans/2026-10-01-interactive-pixel-world-master.md)

## 1. 产品目标

把 QRC-Eye 首页做成一个可探索的俯视角像素世界。访客可以通过角色移动、点击场景物件或普通网页导航发现创作者介绍、开发笔记和项目。每个作品在世界中都有一个可交互的代表物；互动可以打开项目卡片、跳转到现有作品，或启动为该项目单独制作的小体验。

新项目应能通过添加项目资料、场景位置和像素素材接入世界。只有需要独特玩法的项目才新增独立互动模块。

## 2. 成功条件

1. 首次打开首页即进入铺满浏览器视口的可玩像素 RPG；正常状态下不在场景下方显示项目、笔记或关于板块。Canvas、引擎或素材加载失败时，用全屏回退页提供项目和笔记入口。
2. 桌面访客可使用 WASD 或方向键移动，使用 E/Enter 互动；鼠标点击场景物件可直接打开相应说明或项目。
3. 触屏访客可点按场景物件完成互动；不需要滚动网页或打开常规项目目录。
4. 当前首页中的有效项目均通过统一注册表进入场景；增加普通项目时不需要修改场景引擎代码。
5. 每个物件有稳定、可测试的互动类型；新增的专属小游戏可按需作为延迟加载的体验模块接入。
6. 构建产物能在 GitHub Pages 当前根路径部署，不依赖运行时外部 CDN。
7. 自动化测试覆盖数据校验、移动/碰撞、互动路由、构建产物、桌面键鼠、触屏操作和无引擎降级。

## 3. 用户体验与世界设定

### 3.1 场景结构

以创作者工作室和周边小镇为主场景。第一版包含：

| 场景物件 | 首页内容 | 互动结果 |
|---|---|---|
| 工作台 / 公告板 | 创作者介绍、制作经历、最新笔记 | 打开简介或笔记入口 |
| 骑行驿站 / 路线牌 | CyberTravel | 打开作品预览并可进入游戏 |
| 烟花观景台 | 烟花大师 | 播放短烟花动画、显示作品预览、可进入游戏 |
| 温室 / 发财树 | 赛博发财树 | 播放叶片动画、显示项目入口 |
| 地下遗迹入口 | 王土之下 | 显示更暗的项目预览并可进入游戏 |
| 空地 / 新展台 | 后续项目 | 由注册表添加位置、物件素材和互动配置 |

初始场景采用单张可平移地图，不做开放世界任务、背包、等级、战斗或存档。项目内容继续由各自目录和页面拥有；世界是浏览与进入作品的入口。

### 3.2 控制规则

- 键盘：WASD/方向键移动；E 或 Enter 与最近的有效物件互动；Escape 关闭预览并把焦点还给触发入口。
- 鼠标和触屏：直接点按可互动物件打开预览。场景中的对象不要求访客先走到它旁边才可点击。
- 移动和互动状态不能同时触发；弹窗打开时暂停角色移动，避免键盘输入穿透。
- 物件靠近时显示名称和“E 互动”提示；指针悬停/触屏命中时显示相同名称。
- 项目默认通过世界中的实际物件发现；HUD 保留开发笔记入口。游戏异常或 JavaScript 被禁用时显示全屏静态回退页，不在正常场景背后放置可见项目列表。
- 音频默认关闭。第一版不要求角色语音或场景环境音。

### 3.3 视觉基调

使用清晰的俯视角像素艺术。主要颜色来自夜蓝、石墨灰、暖黄灯光和少量薄荷绿/砖红点缀；保留游戏作者工作室的酷感，避免 CRT 扫描线、系统启动字样和终端荧光色作为主视觉。动画以待机、行走、物件反馈和烟花短效果为主，避免持续闪烁。

首个可玩原型以 16×16 逻辑地砖、16×24 角色帧和 640×360 逻辑视口为起始标尺。该标尺先用于地图/素材原型；W1 完成移动端可读性检查后再最终冻结，不合适时更新此规格，避免画师和程序各用一套尺寸。

## 4. 技术方案

### 4.1 选型建议

| 层 | 方案 | 责任 |
|---|---|---|
| 游戏渲染 | Phaser 4.2.0，精确版本锁定 | 2D 场景、镜头、纹理、动画、键鼠/触控、Tilemap 与碰撞 |
| 类型与模块 | TypeScript + ES Modules | 项目注册表、互动类型、场景/物件接口、可独立测试的规则 |
| 开发与构建 | Vite，版本写入锁文件 | 本地开发服务器、依赖打包、构建可部署静态 JS/CSS/素材 |
| 单元测试 | Vitest | 项目资料、互动解析、碰撞/移动规则、路径安全和工具函数 |
| 浏览器验收 | Playwright Test | 实际 Chromium 场景、页面入口、鼠标/键盘/触控、降级行为 |
| 地图 | Tiled JSON 正交 Tilemap | 地面、障碍、物件层、碰撞属性、出生点和交互区域 |
| 美术资源 | PNG 精灵图 + JSON 帧/动画元数据 | 场景图块、角色与物件动画；源码与构建产物分开管理 |

选 Phaser 的原因是本项目需要持续维护地图、碰撞、角色动画、相机和多种输入。手写 Canvas 引擎会把这些基础能力变成长期维护负担。Phaser 官方文档涵盖 Scene、输入、Tilemap、动画和缩放能力；截至本文日期，官方发布了 Phaser 4.2.0。Vite 负责将运行依赖打包成同源静态文件，适合保持 GitHub Pages 发布方式。

### 4.2 仓库边界与部署

不在仓库根目录新建统一 `package.json`。新增独立 `site-world/` 子项目，里面放场景源码、锁文件、测试、工具配置和源美术。Vite 将生产文件生成到 `assets/world/runtime/`。生成的 runtime 文件纳入版本控制，由现有 GitHub Pages 根目录部署直接提供；`node_modules`、测试报告和缓存不提交。这样不需要改变其他游戏目录的独立依赖，也不需要在页面运行时请求 Phaser CDN。

Vite 入口固定为 `site-world/src/bootstrap/main.ts`，生产入口稳定输出为 `assets/world/runtime/world.js`，样式固定输出为 `world.css`；拆分出的代码块可带内容 hash。根首页只引用这两个固定入口，运行时代码不得保留未打包的 `phaser` bare import 或外部 CDN URL。构建验证同时确认世界地图、tilemap、精灵图等相对资源路径在站点根路径能解析。

主页保持 SEO 元数据、全屏游戏视口和少量语义化 HUD。Phaser Canvas 绘制世界；键位提示、开发笔记入口、项目预览和错误回退继续使用 DOM。项目入口生成在默认隐藏的全屏回退页中，运行时正常时只通过地图物件打开项目面板；运行时失败或访客禁用 JavaScript 时才显示回退页。首页没有场景下方的项目、笔记或关于板块。

### 4.3 代码边界

建议目录：

```text
site-world/
├── src/
│   ├── bootstrap/       # 延迟启动、错误处理、挂载/销毁
│   ├── scenes/          # Boot、World、可选 Overlay 场景
│   ├── entities/        # 玩家、项目物件、交互提示
│   ├── projects/        # 项目清单、schema、互动类型与解析器
│   ├── activities/      # 少量专属体验，按需延迟导入
│   └── ui/              # DOM/场景之间的消息接口
├── maps/                # Tiled 源地图 JSON
├── art/                 # 源 tileset、spritesheet、导出元数据
├── test/                # Vitest 与 Playwright 测试
├── package.json
├── package-lock.json
├── tsconfig.json
└── vite.config.ts

assets/world/runtime/    # Vite 生成并提交的静态运行文件
```

单向依赖：项目数据和纯逻辑不依赖 Phaser；场景/物件调用纯逻辑；DOM 页面通过一个小型消息接口接收场景事件。现有项目页面不会反向依赖主页引擎。

### 4.4 项目物件扩展接口

每个项目由一个可校验的记录描述：

| 字段 | 约束 |
|---|---|
| `id` | 稳定、唯一的短 ID |
| `title`, `status`, `summary` | 项目卡片内容，使用现有首页数据语义 |
| `href` | 可选同源项目页面路径；已有试玩页必须提供并通过目标存在检查；规划中/制作中的地点可以没有 `href`，此时预览显示状态而不渲染失效 CTA |
| `position` | Tilemap 世界坐标或地图对象 ID |
| `spriteKey` | 已登记的物件静态图/动画资源键 |
| `interaction` | 受限的判别联合：`panel`、`navigate`、`activity` |
| `hitArea` | 可交互区域，独立于纯装饰外观 |

普通新项目只需新增记录、放置地图物件和提供素材；`panel` 由通用预览面板处理，`navigate` 跳转现有页面。`activity` 必须引用代码中显式登记的体验模块 ID；不允许从内容数据执行任意模块路径或脚本。每个专属体验实现共同接口，并且在用户触发前不下载它的专属资源。

初始所有项目对象都至少有 `panel` 预览；只有状态为可玩或开放参与且确实有页面的项目才带有效 `href`。当前首页中的王土之下标记为“制作中”，但 `kings-field/index.html` 目标目前不存在，因此它以无链接的规划项目预览呈现，不能生成坏链接。烟花、浇水、游戏机按键等独特小互动可逐步增加；如果主项目页面本身已是完整游戏，默认由预览卡片进入原项目页。

## 5. 兼容、可访问性与降级

- HUD、操作说明、开发笔记入口、项目对话框和全屏错误回退均为真实 HTML；Canvas 中的文字提示不能成为唯一信息来源。
- `Tab` 可到达“查看项目”“控制说明”和弹出的预览操作；预览打开时正确设置焦点，关闭时恢复焦点。
- `prefers-reduced-motion` 下关闭非必要环境动画、相机缓动和循环粒子；移动不依赖动画判断。
- WebGL 不可用时让 Phaser 尝试 Canvas renderer；Phaser/资源/脚本加载失败时隐藏空 Canvas 并在原全屏视口内显示静态入口。
- 小屏采用专门布局，保证场景高度和操作目标可用；触摸目标至少 44 CSS 像素。场景缩放不得拉伸像素宽高比。
- 正常游玩时不显示项目卡片目录；键盘或指针可直接与地图物件互动。异常回退页使用真实项目链接，画布有名称与键位说明。
- 页面继续提供 `prefers-reduced-motion` 支持；任何“音效开启”需用户主动操作。

## 6. 质量门槛

### 6.1 自动化验证

`site-world` 至少提供这些脚本（名称在实施时固定）：

```text
npm run typecheck
npm run test:unit
npm run test:e2e
npm run build
npm run verify:dist
```

`verify:dist` 检查构建目录只含允许的运行文件、主页引用均存在、运行期资源为同源路径、所有 `href` 都能在当前仓库解析；构建前后生成文件应可复现。CI 安装锁文件依赖后依次运行 typecheck、unit、build、dist 检查和 Chromium E2E。

### 6.2 必测用例

1. 注册表拒绝重复 ID、缺失资源键、无效互动类型、越界坐标和不存在的相对链接。
2. 角色撞到地图阻挡层时不能穿透；移动方向、待机方向和动画状态切换正确。
3. E/Enter 只互动当前最近的有效物件；关闭面板后控制恢复。
4. 鼠标/触控点项目物件时打开正确预览，预览入口抵达项目页面。
5. 当前全部项目都有且只有一个有效入口；新增记录不会要求修改通用渲染器。
6. 手机 viewport 下游戏铺满可用视口，HUD 目标尺寸和场景触屏互动可用。
7. 禁止加载 world runtime 时，页面切换到全屏错误回退页并保留项目链接。
8. 资源缺失或加载超时显示失败入口，不留黑屏，不产生未处理异常。
9. 减少动态效果偏好关闭装饰动画；键盘仍可操作。
10. 构建产物中的 JS、CSS、地图和图片全部可从生产根路径访问，无路径 404。

### 6.3 性能初始预算

- 首屏优先绘制 HUD 和游戏 viewport；作品项目不提前嵌入，专属活动不在用户互动前执行。
- 初始世界 JS gzip 目标 ≤ 500 KiB，首屏地图/角色/必要 UI 纹理总量 ≤ 1 MiB；项目专属演示素材按互动时加载。
- 引擎失败时全屏静态回退页可立即使用；移动端 Lighthouse Performance ≥ 80，具体记录测试环境和报告。
- 若 Phaser 最小场景实测超过预算，先做动态导入、素材压缩和移除无用 renderer feature；不得静默下调预算。

## 7. 范围外

- 全量 RPG 玩法：任务线、背包、等级、战斗、多人和长时间存档。
- 把所有已有游戏嵌入主页 Canvas 或把游戏目录重写为 Phaser 项目。
- 必须移动角色才能访问主页信息或进入作品。
- 依赖用户账户、后端数据库或第三方分析服务。
- 3D 场景、自由编辑地图的线上后台和由访客上传内容。

## 8. 实施前约束

当前工作区在 2026-10-01 有未提交改动，包括 `index.html`、`CONTEXT.md` 和多个未跟踪目录。实施前先逐项检查当时的工作区差异；不得用规划中的首页结构覆盖用户已有改动。首次改动只碰 `site-world/` 新子项目及与主页挂载有关的明确文件，并保留博客生成器标记区。
